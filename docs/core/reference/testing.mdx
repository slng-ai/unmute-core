The library ships the runner its own examples use. It runs your project as written: your entrypoint, your tools, your model. A scripted caller types each line, and the runner checks what the agent said.

## Run it

Run it inside your project's environment, from the project folder.

```bash
python -I -m unmute_core.testing converse livekit agent scenarios/*.json   # whole calls, real model
python -I -m unmute_core.testing converse pipecat bot scenarios/*.json
python -I -m unmute_core.testing smoke livekit agent                       # one turn, no network
python -I -m unmute_core.testing smoke pipecat bot --live                  # one turn, real model
```

1. `converse` runs each scenario file as one call. It prints the transcript, the tools called and the model requests per turn. It exits 1 when a scenario fails.
2. `smoke` runs one caller line. Without `--live`, a scripted model answers, placeholder keys fill the environment and no request leaves the machine.
3. `--patch PREFIX` also patches the modules whose name starts with `PREFIX`. Use it when your project builds its session or transport in a shared package.

## What your project needs

| Framework | Your module has | The runner replaces |
|---|---|---|
| LiveKit | `entrypoint(ctx)` and `server`, and builds `AgentSession` in the module | `AgentSession`, with a session that has no room and no speech |
| Pipecat | `bot(runner_args)`, and gets its transport from `create_transport` | `create_transport`, and the SLNG speech services, with text stand-ins |

## A scenario

```json
{
  "name": "Priya files a claim",
  "call_start": {"call": {"direction": "inbound", "calling_number": "+447700900123"}},
  "turns": [
    {"caller": "KP731508, born on the 23rd of January 1992.", "expect": ["Is your policy number"], "max_requests": 2},
    {"caller": "Yes.", "expect": ["Thank you, Priya"], "max_requests": 1}
  ],
  "state": {"policy_number": "KP731508"}
}
```

| Key | What it checks or sets |
|---|---|
| `name` | What the call is. |
| `greeting` | Text the greeting must hold. |
| `turns[].caller` | What the caller says. |
| `turns[].expect`, `turns[].reject` | Text that must, or must not, be in what the agent said that turn. Case is ignored. |
| `turns[].max_requests` | The most model requests the turn may make. An audio run does not cap it. |
| `turns[].language` | The language the line is spoken in on an audio run. |
| `state` | A state path and the value it must hold when the call ends. |
| `call_start` | What `UNMUTE_CALL_START` simulates: the caller's numbers and the values the call starts with. |
| `dispatch` | Start values sent the way a real dispatch sends them. It wins over `call_start`. |
| `refused` | Text your project must log when the call does not start. Give such a scenario no turns. |

A key the runner does not know fails the scenario file. Lines code speaks are word for word, so check them exactly. Check the model's own words loosely, or not at all.

## Settings

| Variable | What it does |
|---|---|
| `CONVERSE_AUDIO` | Run the whole voice pipeline. Each caller line is spoken by SLNG text to speech. Needs `SLNG_API_KEY`. |
| `CONVERSE_REAL_VOICE` | Keep your Pipecat text to speech on a typed run. |
| `CONVERSE_VERBOSE` | Log the library's steps and each tool call's arguments. |
| `CONVERSE_OUT` | Write each call to this folder as JSON. |
| `CONVERSE_CALLER_LANGUAGE` | The language caller lines are spoken in. `en` by default. |
| `CONVERSE_VOICE_CACHE` | Where spoken caller lines are kept. A temporary folder by default. |
| `SLNG_WORLD_PART` | The region that speaks caller lines. `eu-north` by default. |

## Simulate calls

A scripted call proves one path. The call simulator measures an agent: a model plays the caller, each scenario runs many times, and each call is checked by code and by a judge. Two runs, before and after a change, compare check by check.

```bash
python -m unmute_core.testing scenarios                        # the bundled scenarios and agents
python -m unmute_core.testing simulate livekit --calls 10 --out runs/before
python -m unmute_core.testing simulate pipecat booking_happy tag:intake --calls 3
python -m unmute_core.testing simulate livekit --rejudge --out runs/before   # judge again
python -m unmute_core.testing report runs/after --compare runs/before
python -m unmute_core.testing parity runs/livekit runs/pipecat --out parity.md
```

The agent is a real `UnmuteAgent` in a text-only LiveKit session, or `UnmuteFlows` on a Pipecat pipeline with no transport. The bundled agents answer for made-up businesses, and their tools answer from deterministic mocks. A scenario names its agent, so `scenarios/<id>.json` files of your own run the same way.

### The three models

The agent, the caller and the judge each run on any OpenAI-compatible endpoint. Run the caller and the judge on a different model from the agent, so the two sides of the call do not share one model's habits. Keys come from the environment only.

| Flag | Variable | What it sets |
|---|---|---|
| `--model` | `SIMULATE_MODEL` | The model of every role that names none. |
| `--base-url` | `SIMULATE_BASE_URL`, then `OPENAI_BASE_URL` | The endpoint of every role that names none. |
| | `SIMULATE_API_KEY`, then `OPENAI_API_KEY` | The key of every role that names none. |
| `--agent-model`, `--caller-model`, `--judge-model` | `SIMULATE_AGENT_MODEL` and the like | One role's model. |
| `--agent-base-url` and the like | `SIMULATE_AGENT_BASE_URL` and the like | One role's endpoint. |
| | `SIMULATE_AGENT_API_KEY` and the like | One role's key. |
| `--agent-params` and the like | | JSON body fields for one role's requests, like `{"reasoning_effort": "low"}`. The caller sends `{"temperature": 0.7}` unless you say otherwise. The judge always sends temperature 0. |

### A scenario

```json
{
  "id": "booking_happy",
  "agent": "booking",
  "persona": "Sam Ortiz, a regular patient. Polite, efficient.",
  "goal": "Book a check-up and cleaning for {{say:next tuesday}} at 3pm.",
  "facts": {"phone number": "+34 612 345 678 (say it as: plus three four, six one two, ...)"},
  "moves": ["Open by asking to book.", "Confirm your number when it is read back."],
  "expect": {"phone_number": {"phone": "+34612345678"}},
  "known": {"phone_number": ["+34612345678"]},
  "judge_notes": "A plain booking.",
  "tags": ["booking"]
}
```

| Key | What it is |
|---|---|
| `agent` | A bundled agent's name, or a path to an agent file. |
| `persona`, `goal`, `facts`, `moves` | The caller's brief. The caller may give only what `facts` holds. |
| `expect` | Each saved value and the matcher it must meet: `phone`, `exact`, `exact_ci`, `bool`, `present`, `text`, `fields`, `appointment`, `any` or `absent`. |
| `known` | Every value the caller can rightly give, so a saved value outside it is invented. |
| `requires` | What must happen on the way: `task_started`, `mock_called`, `tools_called`, `time_in_availability`, `any_of`, and `injected`, the hidden arguments a mock must receive. |
| `served` | Task names and the words their requests are said in, to catch a served request handed back. |
| `judge_notes` | What the judge should know about this call. |
| `turn_cap` | The most caller turns before the call is cut off. 18 by default. |
| `line` | The caller's number and the call's direction. |

`{{date:next tuesday}}`, `{{date:+7}}` and `{{date:today}}` fill an ISO date in the agent's time zone. `{{say:next tuesday}}` is the same day the way a caller says it.

### Scored calls

A call passes when it passes every core check. Only a call that says something about the agent is scored. These calls are left out of every pass rate, counted apart and named in the summary:

| Left out | When |
|---|---|
| `environment` | The agent's endpoint failed: a rate limit, a 5xx, a timeout or a lost link that lasted through the retries. |
| `harness` | The simulator itself broke, like a turn that never went quiet. |
| `judge` | The judge gave no verdict. Run `--rejudge` later. |
| `caller` | The simulated caller left its brief: it gave a value its facts do not hold, or did the opposite of a move. The judge rules on this. |

A request the endpoint refused as invalid is the agent's error and fails the call, as does a call that failed. A saved value the caller made up is reported as `caller_off_script_value`, not as `fabricated_value`. A rerun into the same folder skips calls with a verdict and runs `environment` and `harness` calls again.

### In CI

```bash
python -m unmute_core.testing simulate livekit --no-judge --retry-failed 1 --gate --out runs/ci
```

`--gate` exits 1 when a planned call has no result, when fewer than `--gate-min-scored` of the planned calls are scored (0.75 by default), or when the scored calls' pass rate is below `--gate-min-pass` (1.0 by default). The verdict goes to `gate.json`, and to the job summary when `GITHUB_STEP_SUMMARY` is set. `--retry-failed N` runs a failed call again up to `N` times. The last attempt counts, the earlier ones stay beside it, and a call that passed only on a retry is listed as flaky.

### What a run writes

| File | What it holds |
|---|---|
| `calls/<scenario>/<nn>.jsonl` | One call: the call record, the timeline (lines, task events, saves, tool calls, model requests), the mock requests, the judge's transcript and reply, and the checks. |
| `run.json` | The framework and each role's model and host. Never a key. |
| `summary.md`, `summary.json` | Pass rates per scenario, failures per check and category, model requests and latency. |
| `gate.json` | The gate's verdict, with `--gate`. |
